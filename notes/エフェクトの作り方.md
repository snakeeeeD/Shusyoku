# エフェクトの作り方

2026-11-16 時点。
- 爆発の火の玉：エフェクト用シェーダー（温度方式）で作った。
- 当たった時の火花：速さの向きに伸ばす粒で作った。
- エフェクトのコードを、種類ごとのファイルに分けた。
- 衝撃波：地面に広がる輪と、輪から立ち上がる壁（最後に割れて破片が散る）を、新しい種類として足した。爆発と、敵の範囲攻撃に使っている。
- 移動の手応え：キャラが動くときの土ぼこり・跳ねる・残像・光る跡（`MoveFeel`）。
- 画面のエフェクト：フィールドではなく画面に貼る演出。HPが低いときの赤み、毒のときの端のもや＋しずく、毒の瘴気（パワーカード）で下から広がる霧（7章）。

---

## 1. 考え方：「種類」と「動き・見た目」に分ける

1つの演出（effects.json の `id` 1つ）は、いくつかの**部品**でできている。
- 例：当たった時（`hit`）＝ 閃光2つ ＋ 赤・橙・黄の線3つ。どれも「粒」の部品。
- 例：爆発（`explosion`）＝ 火の玉（粒）＋ 輪 ＋ 壁。

部品には**種類**がある。種類ごとにファイルが分かれている（5章）。
| 種類 | 中身 | ファイル |
|---|---|---|
| 粒（`burst`） | 小さい絵をたくさんばらまいて、速さ・重力・空気の抵抗で動かす | `ParticleBurst.h / .cpp` |
| コマ送りの絵（`sheet`） | 1枚に並べたコマを順番に出す（斬撃など） | `SpriteSheet.h / .cpp` |
| 輪（`ring`） | 地面に寝かせた輪の絵を、大きく・薄くしていく | `GroundRing.h / .cpp` |
| 壁（`wall`） | 上の縁がとげとげの円柱を、外へ傾けながら広げ、最後に割れて破片を散らす | `ShockWall.h / .cpp` |
| 画面（`screen`） | エフェクト用シェーダー（2章）で、画面いっぱいに1枚描く（瘴気など） | `ScreenOverlay.h / .cpp` |

粒の部品は、さらに「動き」と「見た目」に分けて考える。
| | 担当 | 書く場所 |
|---|---|---|
| **動き**（どこから出て、どう飛んで、いつ消えるか） | 粒。CPUで毎フレーム動かす | `effects.json` の `bursts` |
| **見た目**（粒1つ1つの形・色・消え方） | 画像そのまま（`texture`）か、エフェクト用シェーダー＋部品の画像（`material`） | `effects.json` の `bursts` と `materials` |

1つの演出は「種類 × 動き × 見た目」の組み合わせでできている。
- 爆発の火の玉：粒 × ゆっくり昇る × シェーダー（温度方式）
- 当たった時の線：粒 × 速く散って急に止まる＋速さの向きに伸ばす × 画像そのまま（両端がとがった形）
- 壁の破片：粒 × 外向きに飛ぶ（`forward`）＋速さの向きに伸ばす × 画像そのまま（火花と同じ線の絵）

そのため、**新しい演出はたいてい、データ（effects.json）を書くだけで増やせる。**
今ある種類では作れない動きのときだけ、新しい種類（ファイル）を足す（4章）。輪と壁は、この方法で足した。

## 2. 見た目の仕組み（シェーダー）：「温度」で決める

AAA の講演で聞いた「3枚の画像で爆発を作る」方法。今は爆発の火の玉だけがこれを使っている。

### 部品の画像（3種類、エフェクトどうしで使い回す）
| 画像 | 中身 | 今あるもの |
|---|---|---|
| **形** | 白黒。白い所ほど「中身がある」 | `fx_shape_blob`（ぼかした丸）、`fx_shape_flame`（炎の形） |
| **ノイズ** | もやもやした白黒の模様。端と端がつながっていて、くり返し貼れる | `fx_noise` |
| **色の帯** | 横長の色の並び。**左＝熱い、右＝冷たい** | `fx_ramp_fire`（白→黄→橙→赤→黒煙→透明）、`fx_ramp_smoke`（白っぽい灰→暗い灰→透明） |

画像は `Assets/Particles/` に置いて、`textures.json` に登録する。どれも小さく、全部で数百KB。

### シェーダーの計算（`Shaders/Fx_PS.hlsl`。1ピクセルごと）
1. **ノイズを流す**：ノイズの画像を、時間でずらして読む（UVスクロール）。表面がうねって見える。粒ごとに読む位置をずらす（`Seed`）ので、どの粒も同じ模様にはならない。
2. **温度を出す**：`温度 = 形 × ノイズ − 寿命の進み具合`。中心の、模様の白い所ほど熱い。時間がたつほど冷える。
3. **色を決める**：温度を「色の帯のどの位置か」に使う。熱い＝帯の左（白・黄）、冷えた＝帯の右（赤・煙）。
4. **ちぎれて消える（ディゾルブ）**：寿命が `erodeStart` を過ぎると、「形×ノイズ」が低い所から消えていき、`erodeEnd` で全部消える。境目は少しぼかす。
5. **明るさ**：色に `glow` を掛ける。加算合成（`additive`）なら、下の絵を隠さずに光る。
6. **出てくる順番（出方）**：材質の `appear` が0より大きいときだけ。寿命の最初の `appear` の割合の間に、形の画像の **G** が小さい所から順に出てくる（境目はノイズで少しぎざぎざ）。形の画像の R＝形、G＝出てくる順番、と1枚に2つ入れているので、画像は3枚のまま。白黒の画像は R＝G なので、`appear` を書かなければ今まで通り。瘴気の「下の真ん中から左右へ広がり、端を昇る」はこれで作っている。

1枚の板に貼った同じ画像が、時間とともに「白く光る → 赤 → 黒い煙 → ちぎれて消える」と変わる。コマ送りの画像を何枚も用意する必要がない。

### どちらの見た目を使うか
| 見た目 | 向いているもの | 例 |
|---|---|---|
| 画像そのまま（`texture`） | 小さい・速い・色がはっきりしたもの。色は `colorStart`→`colorEnd` で変える | 当たった時の火花・閃光 |
| シェーダー（`material`） | 大きくて、色が変わりながらちぎれて消えるもの | 爆発の火の玉 |

## 3. データの書き方（effects.json）

### 材質（`"materials"`、ファイルの一番下）
```json
"fx_explosion": { "shape": "fx_shape_blob", "noise": "fx_noise", "ramp": "fx_ramp_fire",
                  "erodeStart": 0.25, "erodeEnd": 0.9, "glow": 1.15, "noiseScale": 1.3, "scroll": [ 0.0, -0.35 ] }
```
| 項目 | 意味 | 調整のめやす |
|---|---|---|
| `shape` / `noise` / `ramp` | 形・ノイズ・色の帯の画像（textures.json のキー） | 色の帯を差し替えると、炎・毒・魔法などを作り分けられる |
| `erodeStart` | 寿命のどこからちぎれ始めるか（0〜1） | 小さいほど早く崩れる |
| `erodeEnd` | 寿命のどこで消えきるか（0〜1） | 1より小さいと、寿命より早く消える |
| `glow` | 明るさの倍率 | 1が素のまま。上げるほど白く飛ぶ |
| `noiseScale` | ノイズの細かさ | 大きいほど模様が細かい |
| `scroll` | ノイズの流れる向きと速さ（[横, 縦]、マイナスで上へ） | 炎は速く、煙はゆっくり |
| `additive` | 加算合成で光らせるか | 炎・光は true、煙は false |
| `appear` | 出てくるのにかかる寿命の割合（0〜1。書かなければ0＝最初から全部出ている）。形の画像の G の順に出る | 大きいほどゆっくり広がる |

### 粒（各演出の `"bursts"` の1つ）
当たった時の赤い線の例：
```json
{ "count": 8, "speed": 14.0, "life": 0.45, "scale": 0.025, "gravity": 4.0, "drag": 0.08, "dragY": 0.08,
  "colorStart": [ 0.95, 0.12, 0.1, 1.0 ], "colorEnd": [ 0.8, 0.05, 0.05, 0.5 ],
  "texture": "fx_streak", "stretch": 0.07, "spread": "screen" }
```
| 項目 | 意味 |
|---|---|
| `count` / `speed` / `life` / `scale` | 数・広がる速さ・寿命（秒）・大きさ（伸ばす粒では幅） |
| `gravity` | 重力（マイナスで昇る） |
| `drag` | 空気の抵抗（横だけ。毎フレーム速さに `1−drag` を掛ける） |
| `dragY` | 縦の空気抵抗（書かなければ0＝今まで通り）。急に止まる動きには `drag` と同じ値を入れる |
| `spread` | 散らし方。書かなければ球状＋やや上向き。`"screen"` で画面に平行な円状（どの向きの線も同じ長さに見える）。`"forward"` で、呼んだ側の向き（`Play` の `rot`。(sin rot, 0, cos rot) の向き）へ飛ばす |
| `cone` | `"forward"` のときの広がり（度）。出す向きから左右・上・下へ、この角度まで散らす（書かなければ30） |
| `stretch` | 0より大きいと、速さの向きに伸ばして描く。長さ＝速さ×`stretch`（直近 `stretch` 秒に進む距離）。速い間は長い線、遅くなると短い欠片。出た所より後ろへは伸ばさない |
| `texture` | 見た目の画像。書かなければ丸い粒（`particle`） |
| `material` | 使う材質（2章）。書くと `texture` ではなくシェーダーで描く |
| `colorStart` / `colorEnd` | 寿命の始めと終わりの色（間はなめらかに変わる）。材質を使うときは白のままでよい |
| `center` | 出る位置を絵の中心にする（材質を使うときは true） |

コマ送りの絵（`"sheets"`）の書き方は、今までと同じ。

### 輪（`"parts"` の `"type": "ring"`）
爆発の輪の例：
```json
{ "type": "ring", "texture": "fx_ring", "life": 0.35, "sizeStart": 0.3, "sizeEnd": 2.4, "ease": 3.0,
  "color": [ 1.0, 0.85, 0.6, 0.9 ], "additive": true }
```
| 項目 | 意味 |
|---|---|
| `texture` | 輪の画像（書かなければ `fx_ring`） |
| `life` | 広がって消えるまでの秒数 |
| `sizeStart` / `sizeEnd` | 最初と最後の直径（ワールド。1マス＝1.1） |
| `ease` | 広がり方の勢い。大きいほど最初に一気に広がり、後はゆっくり |
| `color` | 色。だんだん薄くなって消える |
| `delay` | この輪だけ遅らせる秒数（輪を重ねるとき用） |
| `y` | 地面からの高さ（書かなければ 0.02） |
| `additive` | 加算合成で光らせる（土ぼこりのような輪は false） |

### 壁（`"parts"` の `"type": "wall"`）
爆発の壁の例：
```json
{ "type": "wall", "texture": "fx_wall", "life": 0.35, "radiusStart": 0.14, "radiusEnd": 1.1,
  "height": 0.6, "slant": 0.7, "ease": 3.0, "spin": 0.6, "color": [ 1.0, 0.9, 0.45, 0.9 ], "additive": true,
  "breakAt": 0.55, "breakFx": "wall_shards", "breakCount": 12, "breakHeight": 0.8 }
```
| 項目 | 意味 |
|---|---|
| `texture` | 壁の画像（横＝一周、縦＝上→下。上の縁がとげとげ。書かなければ `fx_wall`） |
| `life` | 立ち上がって消えるまでの秒数（輪と同じにすると、輪にそろう） |
| `radiusStart` / `radiusEnd` | 根もとの半径（最初・最後） |
| `height` | いちばん高いときの高さ |
| `slant` | 外への傾き（高さ1につき、外へどれだけ広がるか）。大きいほどラッパのように開く |
| `ease` | 広がり方の勢い（輪と同じ値にすると、輪にそろって広がる） |
| `spin` | 回る速さ（ラジアン/秒）。とげが止まって見えないように少し回す |
| `segments` | 円柱を何枚の板で作るか（書かなければ32） |
| `color` / `additive` | 色と、加算合成で光らせるか |
| `breakAt` | 寿命のどこで割れるか（0〜1）。割れた後は急に薄くなって消える |
| `breakFx` | 割れたときに縁から出す演出（effects.json の id）。外向きの `rot` を付けて呼ぶので、`"spread": "forward"` の粒にすると外へ散る |
| `breakCount` | `breakFx` を縁の何か所から出すか（呼んだ側の大きさの倍率に合わせて増える） |
| `breakHeight` | 縁のどの高さから出すか（壁の高さに対する割合） |

### 画面（`"parts"` の `"type": "screen"`）
瘴気の例：
```json
{ "type": "screen", "material": "fx_miasma", "life": 1.8, "fadeIn": 0.12, "color": [ 1.0, 1.0, 1.0, 0.6 ] }
```
| 項目 | 意味 |
|---|---|
| `material` | 使う材質（`"materials"` のキー）。見た目はすべて材質で決まる |
| `life` | 出てから消えるまでの秒数（シェーダーの「進み具合」は、この秒数で0→1） |
| `fadeIn` | 出だしにふわっと濃くなる秒数 |
| `color` | 全体に掛ける色。4つ目が全体の濃さ |

出す場所（`Play` の x, y, z）は使わない。画面に貼るので、どこで呼んでも同じに見える。

### 今あるもの
| 演出 | 中身 | 使っている所 |
|---|---|---|
| `explosion` | 材質 `fx_explosion`（丸＋炎の帯）の火の玉3つ ＋ 輪 ＋ 壁（割れると `wall_shards`） | 罠の爆発、全体爆発（`explosion_all`）、ドラゴンの隕石の着弾（敵の `impactVfx`） |
| `wall_shards` | 黄・橙の線（`fx_streak`、`forward`）。壁が割れた時の破片 | `explosion` の壁から |
| `hit` | 閃光2つ（`fx_burst`、赤＋黄、0.08秒）＋ 線3種類（`fx_streak`、赤・橙・黄。伸ばす粒・画面に平行） | 攻撃が当たった時 |
| `enemy_shock` | 白い輪 ＋ 低く控えめな白い壁（割れると `enemy_shock_shards`）。呼んだ側が敵の色を掛ける | 敵の範囲攻撃（下） |
| `enemy_shock_shards` | 白い線1本（`forward`） | `enemy_shock` の壁から |
| `move_dust` / `move_land` | 土ぼこり（`smoke` の絵、`forward`） | 移動の手応え（6章） |
| `move_trail` | 水色の光る点。ゆっくり消える | 移動の手応え（6章） |
| `miasma_screen` | 画面（`screen`）。材質 `fx_miasma`。下の真ん中から左右へ広がり、端を昇って、ちぎれて消える紫の霧（1.8秒） | 毒の瘴気のカードを使ったとき（cards.json の `vfx`）、2ターンに1回の発動のとき |

材質の一覧：
| 材質 | 形 | 色の帯 | 使っている所 |
|---|---|---|---|
| `fx_explosion` | `fx_shape_blob`（ぼかした丸） | `fx_ramp_fire` | 爆発の火の玉 |
| `fx_miasma` | `fx_shape_miasma`（R＝下と左右のU字、G＝出てくる順番） | `fx_ramp_miasma`（明るい紫→暗い紫） | 瘴気（`appear` 0.4） |
| `fx_poison_edge` | `fx_shape_edge`（画面の端の枠） | `fx_ramp_poison`（あざやかな紫） | 毒のときの端のもや（7章） |

材質 `fx_smoke`（丸＋煙の帯）と `fx_fire`（炎の形＋炎の帯、加算）は、今は使っていない（試したが、元の見た目のほうがよかった）。

### 敵の範囲攻撃の衝撃波（`BattleScene::PlayEnemyAreaFx`）
敵の攻撃の範囲の演出は、前は「範囲のマス1つずつに小さい演出」だった。今は、範囲の形で出し分けている。
- **丸く広がる形**（`Area` / `Square` / `Diamond`）で、突進ではなく、着弾の演出（`impactVfx`）が無い攻撃 → `enemy_shock` を出す。
  - 範囲1マスごとに波を1つ。k マス目まで届く大きさ（`scale`）で、0.12秒ずつ遅らせて外へ重ねる。範囲が広いほど波が増える。
  - 中心は、**動く前の位置**（予告の範囲の中心）。範囲の中心が狙ったマスなどのときは、そのマス。2*2 の敵は体の幅のぶん大きくする。
  - 色は敵の識別色（`hueColor`）を掛ける。
- **それ以外の形**（直線・突進など）→ 今まで通り、マス1つずつに `areaVfx`（書かなければ `area_burst`）。突進は走った順に尾を引く。
- **着弾の演出がある攻撃**（ドラゴンの隕石など）→ その演出（今は `explosion`）に任せる。

## 4. 新しい演出の足し方

### A. 今ある種類（粒・コマ送り・輪・壁・画面）の組み合わせで作れるとき：データだけ
1. **今ある部品で作れるか考える**：形・ノイズ・色の帯・画像の組み合わせ。色だけ違うなら、色の帯を1枚足すだけ（横256×縦4ピクセル）。
2. 必要なら `effects.json` の `"materials"` に材質を1つ書く。
3. 出したい演出の `"bursts"` に粒を書く。輪・壁は `"parts"` に書く。
4. **ゲームを起動し直す**（ビルドは要らない）。シェーダーの中の数字を変えた場合も、起動し直すだけで効く。

### B. 今ある種類では作れない動きのとき：新しい種類を足す
1. 種類のファイルを1つ作る（例：`ScreenFlash.h / .cpp`）。小さい見本は `GroundRing.h / .cpp`、データの多い見本は `ParticleBurst.h / .cpp`。
   - `XxxDef`（`EffectPartDef` を継承）：その種類のデータと、JSONの読み方（`static Load`）と、`Spawn`。
   - `Xxx`（`EffectPart` を継承）：出ている演出1つ。`Update`／`Draw`／`IsDone`（必要なら `Stop`）。
   - `Draw` は毎フレーム3回（地面・上・画面の順番）呼ばれる。描きたい順番のときだけ描き、それ以外はすぐ return する（5章）。「上の順番以外なら描く」のような書き方にすると、順番が増えたときに2回描いてしまう（壁で実際に起きかけた）。
2. `EffectKinds.cpp` の表に1行足す（`{ "flash", &FlashDef::Load }`）。
3. effects.json の演出に `"parts": [ { "type": "flash", ... } ]` と書く。
4. vcxproj に足す。フィルタは「描画関連 > 20-Effect > 10-種類」の中に、その種類のフィルタを作って入れる。

`EffectManager` と、ほかの種類のファイルには触らない。輪（`ring`）・壁（`wall`）・画面（`screen`）は、実際にこの手順で足した。

注意：effects.json は、手で整えた書き方（色の配列を1行で書くなど）が混ざっている。プログラムで丸ごと書き直すと見た目が崩れるので、必要な所だけ書き足す。

## 5. プログラムの流れ（どこに何があるか）

```
起動時
effects.json
  ↓ EffectDataBase::Load     … 演出ごとに部品を読む。"bursts" は "burst"、"sheets" は "sheet"、"parts" は "type" の種類
  ↓ EffectKinds::Load(type)  … 種類の表から、その種類の読み方（BurstDef::Load など）を探して呼ぶ
  → EffectDef::parts         … 部品のデータ（EffectPartDef）の並び。起動中ずっと残る

再生
EffectManager::Play(id, x, y, z, rot, delay, tint, scale)
                             … SE・画面の揺れ・時間差の予約・続けて出す演出（then）。部品ごとに Spawn を頼む
  ↓ EffectPartDef::Spawn     … データから「出ている演出」（EffectPart）を作る。EffectManager は種類を知らない
EffectManager::Update        … 出ている演出の全部に Update を呼ぶ。IsDone なら消す
                               （Update の中から Play を呼んでもよい。壁が割れて破片を出すときに使っている）
EffectManager::Draw(layer)   … 毎フレーム3回呼ばれる
  Ground （地面の順番）      … BattleScene::DrawGroundEffects。罠の後・キャラの前
  Overlay（上の順番）        … キャラの後
  Screen （画面の順番）      … 3Dと覚醒演出を全部描いた後・UIの前（BattleScene::Draw で、もう一度 Begin〜End して呼ぶ）
  ParticleBurst              … 上の順番。材質があれば DrawFxBillboard、stretch があれば DrawStreak、なければ DrawBillboard
  SpriteSheet                … 上の順番。コマを進めて DrawBillboard
  GroundRing                 … 地面の順番。地面に寝かせた板（DrawQuad）
  ShockWall                  … 奥半分は地面の順番、手前半分は上の順番（DrawQuad で台形を並べる）
  ScreenOverlay              … 画面の順番。DrawFxScreen（画面いっぱいの板をエフェクト用シェーダーで）
ScreenStatusFx::Draw         … EffectManager の画面の順番の後、UIの前（状態に合わせて出し続ける演出。7章）
```

### 壁がキャラの「後ろ」と「前」に分かれて見える理由
キャラの絵は奥行き（深度）を書かないので、重なりは**描く順番**で決まる。壁を1回で描くと、キャラの上に全部かぶるか、全部隠れるかになる。
そこで壁を、カメラから見た奥半分と手前半分に分けて描いている。
1. 奥半分（カメラから遠い側の板）を、キャラより先に描く → キャラに隠れる。
2. 手前半分（カメラに近い側の板）を、キャラより後に描く → キャラの前に出る。

これで、輪の真ん中に敵が立っていて、壁がその周りを囲んでいるように見える。板ごとに「カメラの側にあるか」を、「輪の中心からカメラへの向き（水平）」と「輪の中心から板への向き」の内積で判定している（プラスなら手前）。カメラの位置は、ビュー行列の逆行列から取る。

| ファイル | 中身 |
|---|---|
| `EffectPart.h` | 基底クラス。`EffectPart`（出ている演出：Update / Draw / IsDone / Stop）、`EffectPartDef`（データ：Spawn）、`SpawnAt`（出す場所・向き・色・大きさ・カメラの向き）、`EffectLayer`（Ground / Overlay / Screen） |
| `EffectKinds.h / .cpp` | 種類の一覧（名前 → 読み方の関数の表）。今は burst / sheet / ring / wall / screen |
| `EffectManager.h / .cpp` | 呼び出し口（Play / Stop / Update / Draw / Clear）。どの種類でも同じ |
| `EffectDataBase.h / .cpp` | effects.json を読む。`EffectDef`（演出1つ）、`FxMaterial`（材質） |
| `ParticleBurst.h / .cpp` | 粒の種類。`BurstDef`（データ）と `ParticleBurst`（出ている粒の群れ1つ） |
| `SpriteSheet.h / .cpp` | コマ送りの種類。`SheetDef`（データ）と `SpriteSheet`（出ているコマ送り1つ） |
| `GroundRing.h / .cpp` | 輪の種類。`GroundRingDef`（データ）と `GroundRing`（出ている輪1つ） |
| `ShockWall.h / .cpp` | 壁の種類。`ShockWallDef`（データ）と `ShockWall`（出ている壁1つ。割れる処理 `Break` も） |
| `ScreenOverlay.h / .cpp` | 画面の種類。`ScreenOverlayDef`（データ）と `ScreenOverlay`（出ている画面の演出1つ） |
| `MoveFeel.h / .cpp` | 移動の手応え（6章）。エフェクトの種類ではなく、キャラが1つ持つ |
| `ScreenStatusFx.h / .cpp` | 状態に合わせて出し続ける画面の演出（7章）。エフェクトの種類ではなく、BattleScene が1つ持つ（`m_screenFx`） |
| `Renderer3D.h / .cpp` | `FxParams`（シェーダーに渡す数字・48バイト。`appear` は空いていた場所を使ったので大きさは変わらない）、`DrawFxBillboard`、`DrawFxScreen`（画面いっぱいの板。頂点を最初から画面の座標 -1〜1 に置き、ビュー・射影を掛けない）、`DrawStreak`（速さの向きに伸ばした板）、`DrawQuad`（4つの角を自由に決めた板。輪・壁で使う） |
| `Shaders/Fx_PS.hlsl` | エフェクト用のピクセルシェーダー。t0＝形（R＝形、G＝出てくる順番）、t1＝ノイズ、t2＝色の帯、b1＝FxParams |

- 敵エディタの演出プレビューは、部品のうち粒とコマ送りだけを取り出して描いている。輪・壁など新しい種類は、エディタではプレビューされない。
- 同じ順番（地面／上）の中では、描く順番は「出た順」。

## 6. 移動の手応え（`MoveFeel`）

キャラが動くときの見た目。プレイヤーと敵の共通の親 `GameObject` が1つ持つ（`m_feel`）。
- `GameObject::StartMove` が `OnMoveStart`（動き始め）を、`UpdateMove` が毎フレーム `Update` を呼ぶ。
- 描くときは、キャラの `Draw3D` が `Lift`（浮く高さ）・`ScaleX` / `ScaleY`（つぶれ・伸び）・`Ghosts`（残像）を読んで使う。プレイヤーは残像だけ使う。

### 動き方（enemies.json の敵ごとの `"moveStyle"`。書かなければ `walk`）
| 動き方 | 見た目 | 使っている敵 |
|---|---|---|
| `walk` | 1マス動き始めるたびに、進む向きと反対へ土ぼこり（`move_dust`） | 足のあるキャラ・プレイヤー |
| `hop` | 1マスごとにぴょんと跳ね（空中で少し縦に伸びる）、着地でつぶれて戻る＋左右へ土ぼこり（`move_land`） | スライム類・キノコ類・ミミックなど、足がなく地面にいる敵 |
| `float` | 何も出さない | 幽霊・コウモリ・ドラゴンなど、浮いている敵 |
| `glide` | 通った跡が光る（`move_trail` を0.03秒ごとに足元へ置く） | 三層のくさび4体 |

- **残像**：間をあけずに続けて2マス以上動いたら、`walk` / `hop` / `float` に残像を付ける（`glide` は光る跡があるので付けない）。少し前の位置に薄い絵を置き、0.18秒で消える。
- 細かい数字（跳ねる高さ・つぶれる量・残像の濃さなど）は、`MoveFeel.cpp` の上の定数にまとめてある。
- 土ぼこり・光る跡の見た目は、ふつうの演出なので effects.json で変えられる。

## 7. 画面のエフェクト

フィールド（3D空間）ではなく、画面に貼る演出。**3Dを全部描いた後・UI（手札・数字・上の帯）の前**に描くので、UIは隠れない。

### 出し方は2通り
| | 一回だけ出す | 状態に合わせて出し続ける |
|---|---|---|
| 例 | パワーカードの瘴気 | HPが低い、毒になっている |
| 仕組み | 種類 `screen`（`ScreenOverlay`）。`EffectManager::Play("miasma_screen")` で出す。ふつうの演出と同じ | `ScreenStatusFx`。毎フレーム「今どの状態か」を受け取り、濃さを目標（0か1）へ0.5秒かけて近づける |
| いつ消えるか | `life` 秒で消える | 状態が終わったら、ふわっと消える |

状態のほうを「出し始め／止める」で作らなかった理由：HPが下がる・回復する、毒が付く・治る場所はあちこちにあるので、止め忘れが起きやすい。毎フレーム状態を見れば、どこで変わっても漏れない。

### 見た目の作り方は、変わり方で選ぶ
| 何が変わるか | 作り方 | 例 |
|---|---|---|
| 色と濃さだけ | 画像1枚に色を掛けて、2D描画（SpriteRenderer）で画面いっぱいに貼る | HPが低いときの赤み（`fx_vignette`：白で、端ほど不透明・真ん中は透明） |
| 形がうねる・ちぎれる・広がる | エフェクト用シェーダー（3枚の方法）で、`DrawFxScreen` | 瘴気、毒の端のもや |
| 1粒ずつ動く | 画像を2D描画で、1粒ずつ位置・大きさを計算して描く | 毒のしずく |

### 今あるもの（`ScreenStatusFx`）
- **HPが低いとき**（最大HPの3割以下）：端が赤くなる。3割以下に**入った瞬間だけ**、ドクン・ドクンを3回大きく鼓動し、その後は明滅しない薄い赤だけ残る（ずっと明滅すると、考えるときの邪魔になるため）。3割を超えるまで回復すると、鼓動もやめる。
- **毒のとき**：
  - 端のもや：材質 `fx_poison_edge` を `DrawFxScreen` で描く。ずっと出すので「進み具合」は0.3で固定し、ノイズだけを流し続ける（時間で冷えて消えることはない）。
  - しずく：上の帯の下の端（`UiContext::BAR_H`）で0.4〜0.55秒ふくらんでから、重力で落ちる。0.45〜0.9秒に1粒。落ちる間は速さに合わせて縦に伸ばす（火花の「速さの向きに伸ばす」と同じ考え方）。落ち始めて0.4秒で薄くなり始め、0.56秒で消える。毒が治ると新しいしずくは出さない。
- **重ねる順番**：毒のもや → しずく → HPの赤み。HPの赤みは「危ない」の合図なので、いちばん上。
- 数字は `ScreenStatusFx.cpp` の上の定数にまとめてある。もやの見た目（色・流れ方）は材質なので、effects.json で変えられる。
- 更新は `BattleScene::Update` の前の方で呼ぶ（覚醒演出・ヒットストップで処理が止まる所より前。鼓動やしずくが途中で止まらない）。

### パワーカードの演出
cards.json の `vfx` に演出の id を書くと、パワーカードを使ったとき、プレイヤーの位置で出す（前は、パワーカードは `vfx` を見る前に処理が終わっていて、出なかった）。毒の瘴気は、2ターンに1回の発動のときも同じ `miasma_screen` を出す（`BattleScene.cpp` のターンの処理）。

### 新しい画面のエフェクトを足すとき
- 一回だけ出すもの：材質を書いて、`"type": "screen"` の演出を作る（データだけ）。広がり方を付けたいなら、形の画像の G に出てくる順番を描いて、材質に `appear` を書く。
- 状態に合わせて出し続けるもの：`ScreenStatus` に状態を1つ足し、`ScreenStatusFx` の Update（濃さを目標へ）と Draw（描く）に足す。

## 8. これから

- **しずく**：重力で落ちる＋速さの向きに伸ばす（伸ばすのはできた）＋地面に着いたら跳ねる（別の演出を続けて出す。まだ）。
- **火の粉**：小さく光る点が、左右にゆらゆらしながら昇る＋明るさがちらつく。粒の動きを足す必要がある。
- **寿命による大きさの変化**（煙がだんだん広がる）も、粒の側に足すとよくなる。
- **画面のエフェクトの続き**：画面のフラッシュ（画像1枚で足りる）、衝撃波で画面がゆがむ（今の画面を読み込んでずらすポストプロセス。三層ボスの覚醒演出のブラーの仕組みが土台になる）。毒以外の状態異常を画面に出すかは、うるさくならないよう絞って決める。
- **破片の色**：敵の衝撃波の破片は白のまま（呼んだ側の色が破片には渡らない）。敵の色にするなら、壁から `breakFx` を呼ぶときに色を渡す。
- **歩きのアニメ**：プレイヤーだけに付ける案がある（敵は今の手応えのまま）。

## 9. 説明するときの要点（面接・資料用）

- **設計**：エフェクトの呼び出しは `EffectManager` で共通にして、仕様（どう動いてどう描くか）は種類ごとのファイルに分けた。基底クラス（出ている演出／そのデータ）と、種類の一覧の表でつないでいる。新しい種類は「ファイル1つ＋表に1行」で増え、ほかの種類には触らない。審査会で言われた「1つのファイルに全部入っている」への答え。実際に、分けた後で輪と壁をこの手順で足せた。
- **見た目**：エフェクトを「動き（粒）」と「見た目」に分けた。見た目は、画像そのままか、形・ノイズ・色の帯の3枚と「寿命の進み具合」からシェーダーで計算する温度方式を、粒ごとに選べる。
- **なぜ**：コマ送りの画像を演出ごとに用意すると、容量も手間も増える。部品を使い回して数字で作り分ければ、新しい演出をデータだけで増やせる。
- **工夫（温度方式）**：色と消え方を「温度」という1つの値から決めたので、冷えていく爆発やちぎれて消える煙を、同じシェーダーで作れる。
- **工夫（火花）**：参考の動画を30コマ/秒で1コマずつ見て、「閃光 → 線が飛ぶ → 欠片になって落ちる」の時間を測り、数字に落とした。動きの側に「速さの向きに伸ばす」を1つ足しただけで、速い間は線・遅くなると欠片という2段階の見た目が、1つの仕組みで出る。
- **工夫（衝撃波の壁）**：キャラは奥行きを書かないので、壁を奥半分と手前半分に分けて、キャラの前と後に描いた。3Dの深度を使わずに、輪の真ん中にキャラが立って見える。割れた破片は、火花と同じ部品（線の絵＋伸ばす粒）を外向きに出しているだけで、新しい絵は作っていない。
- **工夫（敵の範囲攻撃）**：前は範囲のマス1つずつに演出を出していて、広い範囲ほどばらばらに見えた。範囲の大きさに合わせて波の数と大きさを決め、少しずつ遅らせて重ねたので、「中心から外へ広がる攻撃」として読める。中心は予告の範囲と同じ（動く前の位置）にして、予告と演出がずれないようにした。
- **工夫（移動の手応え）**：キャラの種類ごとに動き方を4つに分け、enemies.json の1項目で選べるようにした。足のない敵は跳ねてつぶれる、浮いている敵は何も出さない、など「その敵らしさ」をデータで決めている。
- **工夫（画面のエフェクト）**：
  - 「一回だけ出す」と「状態に合わせて出し続ける」で仕組みを分けた。出し続けるほうは、毎フレーム状態を見て濃さを近づけるだけにしたので、HPや毒がどこで変わっても止め忘れが起きない。
  - 見た目は「何が変わるか」で作り方を選んだ（色と濃さだけなら画像1枚、うねる・広がるならシェーダー、1粒ずつ動くなら2D描画）。全部をシェーダーにはしていない。
  - 「考える邪魔をしない」を優先した。HPの鼓動は入った瞬間の3回だけ、毒のもやは細く薄く、UIの下に描く。
  - シェーダーに「出てくる順番」を足した。形の画像の空いていた G に順番を描くだけなので、画像の枚数も、シェーダーに渡す数字の大きさも増えていない。爆発の見た目も変わらない。
  - 作る前に、Python でシェーダーと同じ計算をして案の絵と見比べ、色や濃さを合わせてからコードにした。
- **結果**：爆発をシェーダー1つと部品画像3枚で、当たった時の火花を画像2枚とデータで作った。衝撃波は、輪と壁の2種類を足すだけで、爆発・隕石・敵の範囲攻撃に使い回せた。瘴気と毒のもやは、爆発と同じシェーダーを、別の画像と数字で使い回して作った。

部品画像を作り直すためのスクリプト（ノイズ・色の帯・形・火花・輪・壁・画面の端の赤み・瘴気・毒のもや・しずくの画像をプログラムで作る）は、今は作業用の一時フォルダにある。残しておきたい場合は `tools/` に移す。
